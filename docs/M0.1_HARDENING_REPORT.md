## Privacy model (as implemented)

| Label                  | Model provider with `allowPersonalData: false` | `allowPersonalData: true`, `cloud` | `allowPersonalData: true`, `local` | External tool / remote client |
| ---------------------- | ---------------------------------------------- | ---------------------------------- | ---------------------------------- | ----------------------------- |
| `public`               | ✓                                              | ✓                                  | ✓                                  | ✓                             |
| `personal`             | ✗                                              | ✓                                  | ✓                                  | ✗ (no policy yet)             |
| `local_only` (default) | ✗                                              | ✗                                  | ✓                                  | ✗                             |
| `secret`               | ✗                                              | ✗                                  | ✗                                  | ✗                             |

Disabled providers receive nothing. Unknown providers receive nothing. A request's label is the most
restrictive label of its items. Any body containing a registered secret value is refused regardless
of label. `location: local` is only accepted for loopback URLs, but a loopback proxy _to_ a cloud
service cannot be detected — configuring one as `local` is the owner's responsibility.

Execution boundary: `src/net/http.ts` is the only module that may call `fetch` or import networking
modules (`tests/boundaries.test.ts`). It sends a body only with a genuine clearance for that origin,
allows only `GET` without one, refuses redirects, and in offline mode reaches loopback only. **Not
covered:** AMOS code that deliberately builds a body from undeclared data via the `build` callback's
closure, or that encodes data into a `GET` URL. These are contract rules for M1 code review.

## SQLite security

Guaranteed (POSIX, once the tests pass on Linux):

- Data directory `0700`, owned by the user, or AMOS refuses to open.
- Database `0600` from creation.
- `-wal`/`-shm`/`-journal` are `0600` because SQLite copies the DB's mode, and any existing ones are
  tightened.
- Symlinks are refused.
- Temporary data stays in memory.

Not guaranteed:

- **Windows:** no checks; it relies on profile ACLs.
- **Filesystems without Unix permissions** (FAT/NTFS mounts): tightening is verified, and fails
  loudly if it doesn't take.
- **Backups:** none are implemented yet. ARCHITECTURE §12 requires them to use `ensurePrivateFile`.
- **Root:** the owner check allows root to use its own files; running AMOS as root is unsupported.
- **Content at rest is not encrypted.** Full-disk encryption is the recommended control (threat
  model, out of scope).

## Timeout behaviour

Guaranteed and tested: the request fails at the headers, idle or total deadline (to within event-loop
timer accuracy), and the four failure kinds are distinguishable. Timers and abort listeners are
released as soon as any abort happens.

Not guaranteed:

- **No separate connect phase.** It is part of `headersTimeoutMs`.
- **DNS lookups already in progress** are not interrupted by the OS: the request fails on time, but
  the lookup may finish in the background.
- **Timers can fire late** under heavy CPU load.
