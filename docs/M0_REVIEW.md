# M0 review (2026-11-20)

An independent check of the M0 implementation against its own documentation, done before the first
Linux deployment and before M1. Everything below was re-verified against the code in commit
`807d564`, not taken from the overnight report.

## Verdict

**M0 is sound and does what its documentation says, with the corrections listed here.** No defect
blocks a Linux deployment of M0. Four findings (F1–F4) must be settled before or early in M1, because
M1 is the first milestone that stores private data and contacts providers.

**Recommendation — protect future commits, without rewriting history:**

1. In this repository only, set the GitHub "noreply" address that GitHub shows under
   _Settings → Emails_ (`<id>+AMOS-GUY@users.noreply.github.com`):
   `git -C E:\StorageFolder\AmosAI config user.email "<id>+AMOS-GUY@users.noreply.github.com"`
2. On GitHub, enable _Settings → Emails → "Keep my email addresses private"_ and
   _"Block command line pushes that expose my email"_. GitHub will then reject any future push that
   still carries the Gmail address.
3. Optional: `TZ=UTC` when committing hides the time zone. Low value, since the docs reveal more.

**About the already-published history:** removing the address from it means rewriting all 7
commits (for example `git filter-repo --mailmap`) and **force-pushing** `main`. That changes every
commit hash. It also cannot undo exposure that has already happened: GitHub's event API, caches and
any clones keep the old data. The repository is one day old with no known clones, so a rewrite now is
as cheap as it will ever be. Even so, it is irreversible and outward-facing, so **I have not done it
and will only do it on your explicit approval.** A `.mailmap` file does _not_ hide anything; it only
changes how names are displayed.

## What M0 does not do (so nobody assumes otherwise)

No server, no model calls, no tools, no database at a real path (only tests open databases), and no
privacy enforcement at any boundary. The `amos` CLI is diagnostics only.
